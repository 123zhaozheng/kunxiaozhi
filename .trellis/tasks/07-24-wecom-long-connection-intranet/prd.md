# 企业微信长连接与内网部署支持

## Goal

让部署在银行内网的 LambChat 通过既有 DMZ Nginx 与企业微信智能机器人建立长连接，并保证企业微信入站附件可下载、Agent `reveal_file` 产生的单个文件可经长连接上传并回传，同时不要求应用节点直接访问企业微信公网域名。

## Background

- 企业微信使用智能机器人长连接模式，连接默认端点为 `wss://openws.work.weixin.qq.com`，消息回复、主动消息和媒体上传协议帧均复用该 WebSocket。
- 企业微信入站图片/文件的内容不直接包含在帧内；回调提供动态 HTTPS 下载 URL 和 AES key，SDK 另发 HTTP 请求下载并解密。
- 银行网络已在 LambChat 与企业微信之间部署 DMZ Nginx。本任务不负责设计 DMZ 网络拓扑或实施 Nginx，只定义应用侧所需的网络配置契约，并给出配套 Nginx 配置要求。
- 当前项目的 `WeComBot` 已接受 `websocket_url`，但 Persona schema、Mongo 持久化、API 和 UI 均未暴露或保存该字段，因此实际配置仍回退官方地址。
- 当前 `wecom-aibot-sdk==1.0.8` 是社区增强包；WebSocket 支持 `ws_url/ws_options`，入站附件下载使用独立 `httpx.AsyncClient`。只改 WebSocket URL 不会改变附件下载路径。
- 当前出站 `reveal_file` 链路已实现：校验本轮文件归属，最多选一个文件，从内部存储读取，通过 WebSocket `upload_media` 获取 `media_id` 后回复/主动发送。

## Requirements

- R1：提供显式的企业微信网络配置，覆盖 WebSocket 长连接和入站媒体 HTTPS 下载，不依赖应用节点直接访问公网。
- R1.1：企业微信网络配置放入现有系统设置，由管理员在 Web 设置页手动维护；配置为部署级全局设置，不放在 Persona 企业微信配置中。
- R1.2：普通用户不可查看或修改企业微信网络配置；敏感代理凭证在读取接口中脱敏，并复用现有秘密设置的存储规则。
- R1.3：管理员保存企业微信网络设置后立即重启全部企业微信机器人连接，使新配置生效；不得重启 LambChat Web/API 服务，也不得影响 Web 聊天。
- R1.4：多实例部署通过现有 Redis 设置广播触发，各节点只重启本节点实际持有租约的机器人连接，避免重复连接互踢。
- R1.5：网络配置作为一个原子对象一次保存、一次广播、一次重连，不得因逐字段更新触发多轮机器人重启。
- R1.6：应用保留上一版有效网络配置；新配置使所有已启用机器人在验证窗口内均无法鉴权时，自动回滚上一版配置并恢复旧连接，同时向管理员返回明确失败结果。
- R1.7：只要至少一个已启用机器人通过新配置鉴权成功，就保留新配置；页面逐项显示失败机器人及原因，单个机器人的 Secret 或自身配置错误不得阻断其他机器人。
- R2：默认公网部署保持向后兼容；未配置网关/代理时仍使用企业微信官方端点。
- R3：网络配置须区分“DMZ 反向代理端点”与“HTTP(S) CONNECT 正向代理”，避免把正向代理地址误当企业微信业务 URL。
- R3.1：管理员可选择 `direct`（公网直连）、`reverse_gateway`（DMZ 反向网关）或 `forward_proxy`（HTTP(S) 正向代理）三种模式；默认 `direct`。
- R3.2：`reverse_gateway` 分别配置 WSS 网关地址与入站附件下载网关地址；`forward_proxy` 配置代理地址、可选凭证和不走代理的目标列表。
- R4：若采用反向代理端点，WebSocket 必须支持自定义 `wss://` 地址，入站媒体动态 URL 必须按受控规则路由到 DMZ 网关，并保留原始目标主机/路径语义。
- R5：若采用正向代理，WebSocket 与 HTTP 媒体下载必须使用同一显式代理策略；内部 S3、MongoDB、Redis、模型服务和 LambChat 自身地址不得误走该代理。
- R6：TLS 校验默认开启；自签/行内 CA 通过 CA bundle 配置解决，不提供默认关闭证书校验的方案。
- R7：附件链路具备大小限制、超时、错误日志和可诊断状态；网络或附件失败不得中断纯文本回答。
- R8：Agent 出站仅交付当前用户、session、trace 下由 `reveal_file` 揭示的第一个合格文件，不新增企业微信专用工具。
- R9：提供 `.env.example`、容器/Kubernetes 部署示例、Nginx 必需行为说明和连通性验收步骤，敏感凭证不写入普通配置或日志。
- R10：新增单元/集成边界测试，覆盖默认公网、自定义 WebSocket、代理/媒体下载路由、TLS 配置及 `reveal_file` 回传不回归。

## Acceptance Criteria

- [ ] 应用可在无公网直连条件下，通过一种明确选定的 DMZ Nginx 接入模式完成企业微信 WebSocket 鉴权并维持心跳。
- [ ] 管理员可在系统设置页配置、保存和验证企业微信网关参数，普通用户无权修改。
- [ ] 保存网络配置后所有机器人连接立即按新配置重建；Web/API 服务持续可用，连接状态能显示重连成功或具体失败原因。
- [ ] 新配置导致全部已启用机器人鉴权失败时自动恢复上一版配置和连接；页面显示“已回滚”而不是误报保存成功。
- [ ] 新配置出现部分成功时不回滚，成功机器人保持在线，失败机器人及脱敏原因在管理员页面清晰可见。
- [ ] 企业微信发送图片或文件后，LambChat 能通过同一 DMZ 出网策略下载、AES 解密、写入内部存储并传给 Agent。
- [ ] Agent 调用 `reveal_file` 后，当前运行的首个合格文件能经企业微信媒体上传协议回传，额外文件和越权文件被忽略或拒绝。
- [ ] 未配置 DMZ 网络参数的现有部署行为不变。
- [ ] 三种模式均有模式相关字段校验；页面只显示当前模式需要的字段，不允许把正向代理地址误用为企业微信业务端点。
- [ ] 配置错误、TLS 错误、下载超时和媒体上传失败均能通过状态/日志定位，且不泄露 bot secret、下载签名参数或文件内容。
- [ ] 运维文档明确列出应用配置、Nginx 行为、允许的目标域名/端口、超时和验证命令。

## Out of Scope

- DMZ 区域划分、防火墙审批、Nginx 主机部署和证书签发的实际实施。
- 改为企业微信自建应用 HTTP 回调模式。
- 多文件回传、`reveal_project` 回传或绕过现有文件归属校验。
