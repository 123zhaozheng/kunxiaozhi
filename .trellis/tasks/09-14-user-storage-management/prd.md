# 用户存储空间管理与文件删除状态

## Goal

为每个用户提供可见、可控、不可绕过的个人存储空间管理能力，防止持续上传耗尽服务端本地磁盘或对象存储；用户清理文件后，历史会话仍保留附件上下文并明确显示文件已删除，Agent 也能可靠识别该 URL 已不可用并提示重新上传。

## Product Value

- 保护部署方的存储容量，避免单个用户无限占用空间。
- 让用户清楚知道已用空间、剩余空间和需要清理的文件。
- 清理真实释放可计费空间，同时不破坏历史会话的可读性。
- 为 Agent 和前端提供稳定的“文件已删除”语义，避免把删除误判为网络故障。

## Confirmed Facts

- 主上传入口 `POST /api/upload/file` 已有单文件大小、单次数量、危险后缀和角色权限限制，但没有按用户累计空间配额。
- 当前 `file_records` 以内容哈希全局去重，`uploaded_by` 只表示首个上传者，不能安全表达多个用户分别拥有同一物理对象。
- 当前签名 URL、按 key 删除和哈希去重存在归属校验缺口；新增空间管理不能继续暴露或删除其他用户的文件。
- 当前聊天附件只保存 key、URL、名称、类型、MIME 和大小，没有删除状态；历史消息无法区分“已删除”和“临时加载失败”。
- 个人信息入口是 `ProfileModal`，适合增加一个与现有移动端/桌面端一致的“空间管理”Tab。
- 项目使用 MongoDB 作为持久真相、Redis 作为缓存/任务基础设施；配额正确性不能只依赖 Redis。
- 本地自测需要同时启动 MongoDB、Redis、FastAPI（8000）和 Vite（3001）；仓库没有演示账号，首个注册用户会成为管理员。
- 用户已选择策略 A：个人配额覆盖聊天附件、用户拥有的个人/Persona/Team 头像、个人 Skill 二进制和企业微信入站文件；Agent 生成文件、Reveal 与工具产物保持独立留存域，不混入用户可清理列表。

## Requirements

### R1 — 用户级空间策略

- 系统必须为每个用户计算并持久维护累计已用字节、空间上限、剩余字节和使用率。
- 普通用户的默认个人配额为 1 GiB，达到 80% 进入预警状态，达到 100% 时硬性拒绝新增占用；全局默认、角色上限和单用户覆盖均可由管理员调整，单用户覆盖优先，其次取用户所有角色中最宽松的有效上限，最后使用全局默认。
- 个人配额计入聊天/主上传附件、用户拥有的个人/Persona/Team 头像、个人 Skill 二进制及企业微信入站文件；共享内置/市场源文件不计入，复制到个人 Skill 目录后的实际副本计入。
- Agent 生成文件、Reveal、tool binary 和 Reveal project 不计入个人配额，也不出现在个人文件列表中；它们必须继续使用独立命名空间和现有单文件/会话/版本清理约束，不能借个人空间管理接口被误删。
- 配额检查必须以后端为准，并在并发上传、重试、失败补偿和内容去重场景下保持一致，不能通过直接调用 API 绕过。
- 达到预警阈值时允许上传但明确提醒；达到硬上限时拒绝会增加占用的上传，并返回稳定、可本地化的错误码与当前空间摘要。
- 管理员必须能够通过受控配置调整默认策略；旧用户和旧文件必须有兼容的默认行为及可重算能力。

### R2 — 空间管理 Tab

- 个人信息中新增“空间管理”Tab，移动端和桌面端均可访问。
- Tab 必须展示已用/上限/剩余空间、百分比进度、正常/预警/已满状态和清理建议。
- 用户只能查看自己的可管理文件；列表至少包含文件名、类型、大小、上传时间和生命周期状态，并支持分页、排序或筛选以避免无界加载。
- 用户可以直接删除单个或批量聊天/企微文件；头像和 Skill 文件必须显示占用但通过其所属功能删除或替换，空间管理不能绕过领域关系直接破坏它们。删除前有明确确认，完成后分别展示逻辑删除、已释放字节和物理清理状态，不能把物理保留误报为配额未释放或把失败误报为成功。
- 加载、空列表、错误、部分失败、键盘操作、窄屏和暗色模式都必须有可用状态。

### R3 — 安全清理与删除语义

- 用户只能管理属于自己的逻辑文件；签名 URL、去重检查、查询和删除都必须执行归属校验。
- 删除先立即完成逻辑删除并使该用户的逻辑 URL 不可访问，保留最小 tombstone 元数据供历史会话显示；物理对象仅在完整确认没有其他合法活跃拥有者或进行中的拥有者操作时清理。历史消息引用本身不阻止用户明确删除和物理清理。
- 删除和重试必须幂等；并发上传/删除不能造成负使用量、重复释放或误删其他用户仍在使用的共享对象。
- 已删除 URL 必须返回稳定的不可用状态（例如 HTTP 410 与机器可读 `file_deleted`），而不是继续生成可访问的签名 URL。
- 物理清理失败必须可重试和可观测，不能恢复文件的逻辑可访问状态或重复占用用户配额。

### R4 — 会话附件与 Agent 行为

- 历史消息必须保留已删除附件的名称、类型和原始大小，不从会话内容中移除卡片。
- 已删除附件卡片必须显示红色删除线和“已删除”文字/图标，禁用打开、下载和预览；状态不能只依赖颜色表达。
- 新增生命周期字段必须保持向后兼容：没有状态字段的旧事件仍按现有可用附件处理，除非服务端确认其 tombstone。
- Agent 读取已删除 URL 或接收包含已删除附件的上下文时，必须得到明确的不可用信号并提示用户重新上传，不得伪造文件内容。
- 签名 URL 过期、权限不足、网络错误和已删除必须保持不同语义，避免把所有加载失败都渲染成“已删除”。

### R5 — 上传体验

- 前端上传前应刷新/预检空间摘要，在明显超限时快速阻止并引导用户进入空间管理，但最终仍以服务端原子校验为准。
- 上传过程中若服务端判定配额不足，当前草稿和其他已选附件必须保留，用户可以清理空间后重试。
- 进入预警区间后，上传成功提示必须同时提醒剩余空间和清理入口。

### R6 — 兼容、运维与验证

- 现有合法上传、头像/技能等受保护资源、历史消息、旧版跨用户内容去重对象和本地/S3 后端不能因升级被误删或失去访问能力；无法证明完整归属的旧对象必须隔离为不可清理状态，而不是猜测归属。
- 必须提供从旧 `file_records`/实际对象重建使用量的可重复校验路径，并报告孤儿、缺失对象和不一致记录，不静默篡改未知数据。
- 后端需覆盖配额并发、去重归属、软删除、共享物理对象、重试补偿和 410 契约；前端需覆盖摘要、限额错误、批量删除、历史恢复和已删除卡片。
- 最终必须在运行中的前后端及临时 MongoDB/Redis 上完成注册、上传、预警/限额、清理、历史会话删除态的浏览器自测，并提供可点击预览入口；无模型密钥时只声明已验证文件生命周期，不宣称 LLM 对话端到端已验证。

## Acceptance Criteria

- [ ] AC1：同一用户的并发上传不能让已用空间超过硬上限；失败上传不会永久占用配额，重复请求不会重复计费。
- [ ] AC2：低于预警阈值、达到预警阈值和达到硬上限三种状态在 API 与空间管理 Tab 中一致；硬上限返回稳定错误码和最新摘要。
- [ ] AC3：空间管理 Tab 在移动端/桌面端显示准确摘要和用户自己的分页文件列表；聊天/企微文件可单个及批量删除，头像/Skill 文件显示清晰的所属功能管理入口。
- [ ] AC4：用户不能查询、签名、复用或删除其他用户的逻辑文件；跨用户相同内容不会泄露元数据，删除一方不会影响另一方。
- [ ] AC5：删除后该逻辑 URL 返回 HTTP 410/`file_deleted`，再次删除保持幂等；逻辑结果、已释放字节与物理清理状态分别返回；完整确认没有活跃/进行中拥有者时后台最终删除物理对象并可重试失败任务。
- [ ] AC6：历史会话仍显示附件卡片，名称/类型/大小保留，卡片有红色删除线和“已删除”标识，且无法预览或下载。
- [ ] AC7：Agent 面对已删除附件得到明确不可用信号，并能提示重新上传；URL 过期或网络失败不会被错误标记为已删除。
- [ ] AC8：旧消息和旧文件升级后保持兼容；重算工具能发现并报告使用量/对象不一致。
- [ ] AC9：聚焦后端测试、前端类型检查/构建/测试、Lint 与差异检查通过；运行中的 MongoDB、Redis、后端和前端健康，浏览器自测路径可访问。

## Out of Scope

- 恢复已删除文件的回收站体验；本任务采用立即逻辑不可用、延迟物理清理。
- 病毒扫描、内容审核、全局文件类型白名单或替换现有危险后缀规则。
- 购买/计费套餐、在线扩容支付和用户间转移空间。
- 在未提供模型 API 密钥时验证真实 LLM 对已删除文件的自然语言回答质量。
- 将 Agent 生成文件、Reveal、tool binary、Reveal project 纳入个人配额或个人文件清理列表；这些产物继续使用独立留存域，独立聚合配额可作为后续任务。

## Product Decisions

- 采用策略 A。
- 默认个人配额 1 GiB；80% 预警，100% 硬拦截。
- 允许管理员按角色和单用户覆盖，解析优先级为单用户 > 最宽松角色 > 全局默认。
- 新写入不再跨用户复用物理对象，只允许同一用户、同一来源的逻辑去重。旧版跨用户共享对象通过独立 blob/owner 模型重建归属；无法完整重建的对象保持隔离且不可删除，任何查询、签名或删除均不能泄露另一用户的元数据。
- 删除立即逻辑不可用，不提供回收站；物理对象在没有其他活跃用户拥有者时异步清理。
- Agent 使用的稳定文件 URL 继续可匿名获取，但新逻辑 URL 必须先解析不可猜测的文件 ID 和 tombstone，且不得绕过删除状态。已签发的旧 S3 URL 在自身短 TTL 到期前无法严格撤销；新客户端不再签发这类 managed-file URL，旧共享对象完成轮换前不允许用户删除。
