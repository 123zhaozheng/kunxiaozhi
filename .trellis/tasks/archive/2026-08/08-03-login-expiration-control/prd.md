# 登录空闲超时管控

## Goal

管理员可在管理后台配置登录空闲超时时长；默认 3 小时。用户连续超过该时长没有真实操作时，当前登录会话失效，前端清理认证状态并要求重新登录。

## Background

- 当前访问令牌默认 24 小时，刷新令牌默认 7 天（`src/kernel/config/base.py:246-247`）。
- 当前刷新令牌会滚动续期，因此仅调整 JWT 到期时间不能表达“连续无操作 3 小时”的空闲策略。
- 密码、OAuth、OA SSO 三种登录入口分别签发 JWT（`src/infra/user/manager.py`、`src/infra/auth/oauth.py`、`src/infra/auth/oa_login.py`）。
- 认证依赖统一位于 `src/api/deps.py`；WebSocket 连接也从该模块完成首次认证。
- 前端 `authFetch` 已在 401/刷新失败时清理登录态并跳回登录页，但目前没有全局真实用户活动监测。
- 管理后台已通过安全/JWT 设置分组渲染数字配置，但数字定义目前没有通用最小值/最大值校验。

## Requirements

### R1. 管理员配置

- 新增安全/JWT 设置 `LOGIN_IDLE_TIMEOUT_HOURS`，默认值为 `3` 小时。
- 管理后台展示清晰的本地化说明，明确这是“最后一次真实用户操作后”的空闲超时，而不是 JWT 固定寿命。
- 配置允许 `0.25` 至 `168` 小时，并通过后端校验；非法值不得保存。
- 保存后无需重启。后端以当前配置判断现有会话：缩短配置可使已超过新阈值的会话立即失效；延长配置不能恢复已经失效的会话。

### R2. 独立登录会话

- 每次密码、OAuth 或 OA SSO 登录均生成独立会话 ID，并在服务端记录用户 ID 与最后活动时间。
- 访问令牌与刷新令牌均携带相同会话 ID；刷新必须保留原会话 ID，不得创建新登录会话或绕过空闲上限。
- 同一登录会话在多个浏览器标签页共享活动状态；不同设备或不同登录产生的会话互不续期。
- 服务端会话活动状态存储在 Redis，并设置与刷新令牌生命周期相匹配的清理 TTL。

### R3. 真实用户操作

- 鼠标/指针点击、键盘输入、触摸以及滚轮操作视为用户活动。
- 前端对活动上报节流，避免高频事件造成请求风暴。
- 后台轮询、令牌刷新、SSE 数据、WebSocket 心跳或服务端推送均不得更新最后活动时间。
- 页面重新变为可见时只检查会话状态，不应仅因切回页面而自动续期。

### R4. 服务端强制执行

- 所有受保护 HTTP API 在完成 JWT 校验后，还必须验证会话存在且未超过当前空闲时长；认证缓存不得绕过此检查。
- 刷新接口和 WebSocket 首次连接执行同样检查。
- 已建立的 WebSocket 与 SSE 长连接必须周期复核空闲状态；服务端心跳/推送不续期，超时后关闭连接或结束流。
- 超时或会话不存在时返回 401 和稳定的空闲超时错误；前端沿用统一退出与安全重定向流程。
- Redis 暂时不可用时不得误报为空闲超时；服务端返回可重试错误，前端保留本地令牌而不是强制退出。

### R5. 前端自动退出

- 已登录前端安装单一的全局空闲会话监测器。
- 监测器在真实操作后节流上报活动，并定期读取服务端权威状态，使没有业务请求的静止页面也能在超时后退出。
- 多标签页通过共享的服务端会话状态收敛；任一标签页的真实活动可延长同一登录会话，其他标签页在下一次状态检查时获得更新后的截止时间。
- 监听 localStorage token 变化，使一个标签页退出后其他标签页立即清理内存认证状态；退出时不得把旧活动时间留给下一次登录。
- 组件卸载、退出登录和用户切换时必须清理事件监听、定时器和在途状态。

### R6. 上线兼容

- 旧令牌不包含会话 ID，部署后不能满足服务端空闲校验，因此首次使用时要求重新登录。
- 本次行为变更应在交付说明中明确：上线时现有登录用户会被统一要求重新登录一次。

## Acceptance Criteria

- [ ] AC1：三种登录入口都创建独立服务端会话，并签发携带同一会话 ID 的访问/刷新令牌。
- [ ] AC2：默认配置下，最后一次真实操作后未满 3 小时的会话可正常访问和刷新。
- [ ] AC3：超过 3 小时没有真实操作后，受保护 API、刷新请求和新的 WebSocket 连接均被拒绝，前端自动回到登录态。
- [ ] AC4：真实交互会延长空闲截止时间；后台轮询、SSE、WebSocket 消息和普通受保护 API 请求不会延长。
- [ ] AC5：刷新令牌轮换保留原会话 ID，不能把已空闲超时的会话恢复。
- [ ] AC6：管理员可在安全/JWT 设置中保存 0.25–168 小时的值，越界值返回 400 且不落库。
- [ ] AC7：配置热更新对未失效会话按当前值生效；已经失效的会话不会因随后延长配置而复活。
- [ ] AC8：同一登录会话的多标签页共享活动，不同登录会话互不影响。
- [ ] AC8a：一个标签页退出后其他标签页同步退出；已建立的 WebSocket/SSE 在服务端复核到超时后关闭，心跳不能续期。
- [ ] AC9：Redis 故障产生可重试错误，不伪装成 401 空闲超时，前端不因此清空令牌。
- [ ] AC10：旧令牌被稳定地要求重新登录，错误路径无 500；上线说明包含一次性重新登录影响。
- [ ] AC11：后端单元/API 测试与前端活动监测测试覆盖正常、边界、超时、配置变更、并发/节流和清理场景。

## Out of Scope

- 从首次登录开始计算的绝对最长在线时长。
- 按用户、角色或设备类型设置不同的空闲时长。
- 管理员查看或手动吊销登录设备列表。
- 限制同一账号的并发登录数量。
- “记住我”选项或登录页视觉改版。

## Key Decisions

- 空闲状态以服务端 Redis 为权威，浏览器本地计时仅用于及时触发状态检查。
- 只有显式真实用户交互调用活动上报接口；普通 API 访问不隐式续期。
- 本期只实现空闲时长；只要持续存在真实操作，会话可以继续在线，不另加绝对最长在线时长。
- 管理配置单位为小时，默认 3，允许 15 分钟到 7 天。
- 上线后旧令牌一次性失效，以保证策略从部署时起完整执行。
