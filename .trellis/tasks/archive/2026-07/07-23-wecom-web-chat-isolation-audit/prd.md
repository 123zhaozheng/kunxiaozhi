# 调研企微连接故障与 Web 聊天隔离

## Goal

确认企业微信机器人 WebSocket 在启动、握手超时、断线和持续重连时，是否会阻塞、拖慢或破坏 Web 端正常聊天会话；给出可验证的根因结论和强隔离方案，使企微通道故障不能影响 Web 聊天的可用性。

## Background

- 2026-07-23 的运行日志显示 `AiBotSDK` 连接 `wss://openws.work.weixin.qq.com` 时发生 `timed out during opening handshake`，随后每 30 秒重连。
- 同期 Web API 仍能响应 `/api/agents`、会话取消、会话查询等请求；该次 Web run 有明确的 `POST .../cancel` 和 `User cancel event recorded`，现有日志不能证明企微超时触发取消。
- 企业微信属于可选外部通道；外部网络、SDK 或企微服务异常不能成为 Web 聊天链路的可用性依赖。
- `src/api/main.py:470-480` 已将企微启动放在后台 task 中，因此不构成 FastAPI 启动门闩。
- 默认 `ARQ_EMBEDDED_WORKER=True`；企微 SDK、HTTP/SSE 和 Agent worker 仍共享 FastAPI 进程与事件循环，没有硬隔离。
- 已确认 `WeComBot.stop()` 未 await SDK disconnect，且握手失败后 `WeComBot.start()` 可误报成功/connected。

## Requirements

### R1. 启动链路审计

追踪应用启动时企微机器人初始化、SDK 建连及重连循环的完整调用链，确认是否存在同步等待、共享事件循环阻塞、启动门闩或未隔离异常。

### R2. 运行时资源与故障传播审计

检查企微连接与 Web 聊天是否共享或竞争以下资源，并说明影响机制：

- asyncio 事件循环、线程池或进程；
- HTTP/LLM 客户端及连接池；
- Redis、MongoDB、任务队列及并发槽；
- Agent 实例、会话状态、取消信号或全局锁；
- 日志、重试风暴及异常传播边界。

### R3. 日志事件区分

区分企微握手超时、自动重连、Web 请求处理和用户主动取消事件，避免把时间相邻但无因果关系的日志误判为同一故障。

### R4. 可验证结论

为每个潜在耦合点提供代码位置、触发条件、预期症状和验证方法；结论必须明确属于以下哪一类：

- 已确认会影响 Web 聊天；
- 理论上可能影响但尚需实验；
- 已被隔离，不构成影响；
- 与当前现象无关。

### R5. 隔离设计建议

给出最小可行修复方案，确保企微初始化失败或持续重连时：

- API 服务仍可启动并保持健康；
- Web 聊天创建、流式响应、取消和会话查询正常；
- 企微错误被记录并反映在通道状态中，但不向 Web 聊天传播；
- 重试具有退避、资源上限和可停止性；
- 可通过自动化测试或故障注入证明隔离成立。

## Acceptance Criteria

- [x] 产出调研报告，包含启动与运行时调用链及准确的 `file:line` 证据。
- [x] 解释用户提供日志中各事件的含义，并判断它们之间是否存在已证实的因果关系。
- [x] 列出所有共享资源和故障传播边界，逐项给出风险等级与结论分类。
- [x] 提供至少一个企微握手超时/持续重连的可控复现或故障注入方案。
- [x] 提供验证 Web 聊天不受影响的测试矩阵，覆盖启动、发起聊天、SSE、取消和会话读取。
- [x] 提供推荐修复设计、备选方案、兼容性风险及回滚路径。
- [x] 调研结论经用户确认后，再决定是否进入实现阶段。

## Out of Scope

- 本任务规划阶段不直接修改企微 SDK、Web 聊天业务逻辑或部署网络配置。
- 不把企微服务本身的可用性问题当作 LambChat 能够消除的问题；本项目负责隔离和降级。
