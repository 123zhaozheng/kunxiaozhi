# 统计看板加载性能根治与版面重排

## Goal

打开统计看板不再触发实时计算：参照 new-api 的预聚合思路，统计数字全部由后台预先算好，
请求只读预聚合结果；同时重排看板版面、替换难看的环图、修复模型名显示成哈希串。

## Background（已确认的根因）

- 前端一次并发约 10 个请求，几乎每个都独立调用 `read_or_freeze`；summary/insights 还各自再算上一周期。
  每次 `read_or_freeze` 会：新建 Redis 连接、缺快照的历史日在请求里当场冻结、
  **今天的数据实时扫 traces（5 条带 `$lookup sessions` 的聚合）**，并对快照集合做 7 次聚合。
- `/users/active`、insights 的峰值与 Token 大户、`/tokens/by-model` 直接扫 traces 并 `$unwind events`。
- `usage_hourly` 只接了 by-model 一个读口，且开关默认关闭。
- 历史日为空时（`not historical_items`）还会额外跑一遍实时回退聚合。
- 默认时间预设是 7 天。
- 模型 token 环图的 label 是 `model_id`（模型配置的 UUID/哈希），未映射为模型显示名。

## Requirements

### R1 请求路径只读预聚合
- 今天的数据由后台 worker 每 60s 刷新进「今日快照」集合；请求读今日快照，不再实时扫 traces
  （今日快照尚未生成的冷启动窗口可回退实时）。
- 历史日继续读不可变日快照；昨天在跨日后由同一 worker 立即冻结，不等每小时一次。
- 快照行新增扩展字段：按小时的用户消息/Token、按模型 Token，供小时趋势、峰值、模型分布使用；
  老快照由 worker 后台补齐扩展字段（核心计数不可变，扩展字段可补）。
- `/users/active`、insights（峰值、Token 大户）、`/tokens/by-model` 全部改读快照结果，不再扫 traces。
- 同一筛选条件的快照读取在进程内单飞 + 短 TTL 缓存：一次看板加载的多个接口共享一次计算。
- Redis 连接仅在确实需要冻结时才创建。

### R2 模型名可读
- 按模型分布返回模型显示名（`model_configs.label`），保留原始 id 供钻取筛选。

### R3 前端
- 进入统计默认选中「1 天」。
- 版面：顶部筛选一行；「数据看板 / 使用明细」两个 tab，使用明细不再坠在看板底部；
  钻取列表替换内容区显示（带返回），不再追加在页面最底部。
- 看板：KPI 行 → 趋势（左 2/3）+ 洞察（右 1/3）→ 智能体 / Persona / 模型三张排名条形卡 → 反馈区。
- 环图替换为排名条形列表（单色、显示数值与占比、可点击钻取、长名截断带悬浮全名）。
- 趋势图去掉双 Y 轴：按指标切换单序列；1 天区间显示 24 小时趋势。
- 显示「数据更新于 HH:mm」。

## Acceptance Criteria
- [ ] 看板加载（1 天）后端对 traces 集合零聚合（今日快照已就绪时）；有单测断言。
- [ ] 同一筛选的并发请求只触发一次快照读取；有单测断言。
- [ ] 今日快照刷新、昨日冻结、扩展字段补齐均在 worker 中完成；有单测。
- [ ] 模型分布 label 为模型显示名、id 为原始模型 id；有单测。
- [ ] 默认 tab 为 1 天；使用明细在独立 tab；无双轴图；无环图。
- [ ] 后端 analytics 相关测试全绿；前端 analytics 测试、tsc、eslint 通过。

## Out of Scope
- `usage_hourly` 写侧与回填（保留不动，读口不再使用，后续可另行移除）。
- 钻取列表（会话/用户/运行/反馈明细）与 PresetAnalyticsModal 的查询实现。
