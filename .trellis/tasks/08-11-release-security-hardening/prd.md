# 上线安全加固审计

## Goal

在项目上线前关闭文件上传与账号首次登录链路中的高风险缺口：不可信文件必须在持久化/解析前失败关闭，所有上线后新建用户必须完成强密码设置后才能进入业务系统。

## Child Task Map

- `08-11-strong-password-first-login`: 强密码、全渠道首次改密、服务端受限状态、凭证版本和前端流程。
- `08-11-upload-file-type-security`: 仅在主文件上传接口增加危险后缀拒绝，关闭 `UNKNOWN` 分类绕过。
- 父任务只负责来源需求、共同安全原则、实施顺序和最终跨链路验收，不直接承载产品代码修改。

## Requirements

- 两个子任务均采用服务端失败关闭策略；前端提示、跳转或 `accept` 不能成为安全边界。
- 安全状态必须持久化或以权威服务端元数据表达，不能信任客户端声明、JWT 非权威字段或历史未验证记录。
- 新字段和历史数据采用向后兼容默认值，避免上线即锁死存量用户或删除历史文件。
- 安全关键变更必须有稳定机器错误码、审计日志、自动化绕过测试以及可操作回滚点。
- 依赖均通过 `uv` 直接声明和锁定，并在上线前复核许可证及 Linux amd64/arm64、Windows 开发环境兼容性。

## Acceptance Criteria

- [ ] 两个子任务各自通过 PRD、设计、实现计划和独立质量检查。
- [ ] OA 新用户拿到的令牌只能完成首次改密，不能利用文件、聊天、Agent 或实时连接接口绕过。
- [ ] 受限用户不能通过主上传接口持久化内容，危险后缀不能通过 `UNKNOWN` 分类绕过。
- [ ] 服务端直接调用、前端流程、SSE/WebSocket、刷新令牌和主上传接口均有回归覆盖。
- [ ] 存量用户和现有合法文件类型保持兼容。
- [ ] 完成全量 backend/frontend lint、type/build 和相关测试，并记录部署、监控与回滚步骤。

## Out Of Scope

- 重建 IAM、替换 OA、MFA、Argon2 迁移。
- 内容检测、异步杀毒/CDR、历史文件清洗、存储/下载授权以及其他上传/导入入口加固。
- 与本次审计发现无关的通用安全重构。

## Key Decisions

- 密码采用 12-64 字符、四类中三类、用户名/邮箱排除、离线 zxcvbn、bcrypt 72 字节上限。
- 所有上线后新建账号渠道首次改密；缺少新字段的存量账号默认已完成。
- 改密/重置使用凭证版本撤销全部旧 token。
- 上传仅采用主接口危险后缀拒绝列表；现有合法类型和其他入口保持不变。
